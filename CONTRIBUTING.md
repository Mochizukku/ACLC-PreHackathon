# Contributing to QR Query (Q2)

Thank you for contributing to QR Query (Q2). 

Q2 is currently being developed as a prototype and system-flow demonstration. Contributions should support the project's current scope, design, and development goals.

## Before Contributing

Before making changes:

1. Read the [README](README.md) to understand the project and its current scope.
2. Review the [PRD](PRD.md) when working on system requirements or behavior.
3. Check the existing issues, tasks, or team discussions to avoid duplicating work.
4. Discuss major changes with the team, manager, or the repository creator before implementing them.

## Development Workflow

The project uses Git and GitHub for version control and collaboration. 

A typical workflow is:

Update your local repository -> Create a branch -> Make your changes -> Test the changes -> Commit the changes -> Push the branch -> Create a Pull Request -> Review and merge

## Branches

Create a separate branch when working on a feature, fix, documentation change, or other independent task.

Use descriptive branch names, such as:

- feature/customer-order-flow
- feature/seller-dashboard
- fix/cart-navigation
- docs/update-readme

# Commits 

Commit messages should clearly describe the change.

Examples:

- feat: add customer menu flow
- fix: correct cart navigation
- docs: update project readme
- refactor: reorganize seller screens

Keep commits focused on related changes rather than combining unrelated work into a single commit.

## Pull Requests

Pull Requests should:

* Clearly describe what was changed.
* Explain any important implementation details.
* Reference the related issue or task when applicable.
* Be tested before requesting review.
* Avoid unrelated changes.

Team members should review changes before merging whenever practical.

## Code and Documentation 

When contributing:

* Follow the existing project structure, language used and coding style.
* Keep implementation simple and appropriate for the current prototype.
* Avoid introducing dependencies without discussing them with the team.
* Update documentation when a change affects documented system behavior.
* Do not add unnecessary functionality outside the current project scope.

## Prototype Considerations

Because Q2 is currently focused on demonstrating the intended system flow, some features may use simulated behavior, predefined data, or prototype implementations.

Contributors should preserve the intended user flow unless a change has been discussed and agreed upon by the team.

## Questions and Discussions 

For unclear requirements or proposed changes, discuss them with the team before making major changes to the project.
